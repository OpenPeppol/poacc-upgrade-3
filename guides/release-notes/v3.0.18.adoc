== BIS documentation

* Release notes
** Clarified the title. These notes cover Peppol BIS 3 documents other than Peppol BIS Billing 3.0 and Peppol BIS Self-Billing 3.0.

* Invoice Response BIS 3.0 (Profile 63)
** Extended to support Invoice Responses to self-billed invoices and credit notes. In self-billing, the Seller sends the Invoice Response to the Buyer that issued the referenced document. The same Invoice Response syntax, validation rules, status codes, and clarification codes apply to both standard billing and self-billing. https://openpeppol.atlassian.net/browse/RFC-575
** Clarified the usage of status Paid with credit-notes. The status code Paid is used to signal that the invoice (debit/credit) is finished, and that no further action is expected. It is not a remittance advice. https://openpeppol.atlassian.net/browse/RFC-587

* Advanced Ordering BIS 3.0 (Profile 65)
** Added a new section describing the business use of the Order Change line status codes, including code 74 - Reopened, which is used to make a previously deleted order line active again. Added a matching entry to the code list chapter, and a note in scenario 2 on when a buyer may reopen a line. Added an Order Change example showing a line being reopened after deletion. https://openpeppol.atlassian.net/browse/RFC-573
**Added Clarification on the Rejection guidance FOR Order Response Advanced section 7.2

* BIS Catalogue with and without response (Profile 1 and Profile 64)
** Added section 6.16 describing the calculations and usage of Product climate data, including a new code list for Item Property Name Codes (IPNC). https://openpeppol.atlassian.net/browse/RFC-540
** Added the missing examples in section 6.16 for net weight, the buyer's item identifier, generic climate data and an Environmental Product Declaration. The examples are catalogue lines.

== Changes to PEPPOL-COMMON rules

The rules below are listed by rule number.

* Changed rule PEPPOL-COMMON-R040 so that a GLN-13 is only accepted with schemeID 0088.
* Updated rule PEPPOL-COMMON-R043 (fatal). A Belgian enterprise number (schemeID 0208) must start with 0 or 1, followed by nine digits, and pass the existing modulo 97 check. A number that starts with 2 to 9 is no longer valid. BIS Billing already uses this check.
* Changed the wording of warning rules PEPPOL-COMMON-R044, PEPPOL-COMMON-R045, PEPPOL-COMMON-R046 and PEPPOL-COMMON-R047 from "must" to "SHOULD". The rules stay warnings. [RFC-558](https://openpeppol.atlassian.net/browse/RFC-558)
* Changed rules PEPPOL-COMMON-R054, PEPPOL-COMMON-R055, PEPPOL-COMMON-R056-1, PEPPOL-COMMON-R056-2 and PEPPOL-COMMON-R057 from warning to fatal. These Dutch identifier rules were introduced as warnings in May 2026. The six-month transition ends with this release. [RFC-541](https://openpeppol.atlassian.net/browse/RFC-541)
** The unit tests now expect a fatal error, matching the rules.
* Added rule PEPPOL-COMMON-R058 as a warning. It checks a Luxembourg VAT number: LU followed by 8 digits, where the last 2 digits are the check digits of the first 6 digits modulo 89. It applies to the seller VAT identifier (BT-31), the buyer VAT identifier (BT-48) and the tax representative VAT identifier (BT-63). The rule becomes fatal in the May 2027 release. https://openpeppol.atlassian.net/browse/RFC-582
* Added rule PEPPOL-COMMON-R059 as a warning. It checks a Luxembourg Register of Legal Persons number (Matricule, schemeID 0240). The number must be exactly 11 digits, digits 5–6 must be a legal form type code from 20 to 99, and digit 11 must be a valid mod-11 check digit. The rule becomes fatal in the May 2027 release. https://openpeppol.atlassian.net/browse/RFC-584
* Added rule PEPPOL-COMMON-R062 as a warning. A VAT identifier that starts with BE must have the form BE, then 0 or 1, then nine digits, and the digits must pass the same modulo 97 check as the Belgian enterprise number. The rule is new in this release, so it is a warning. It becomes fatal in the May 2027 release. BIS Billing has the same rule.

== Changes to transaction rules

* Removed rules PEPPOL-T01-R002 and PEPPOL-T114-R002 (warning). Order and Order Change no longer have to provide a validity end date. https://openpeppol.atlassian.net/browse/RFC-500
* Aligned the text of existing fatal rules with the severity. The checks are unchanged:
** PEPPOL-T01-R028, PEPPOL-T110-R013 and PEPPOL-T114-R028 now say SHALL NOT instead of "cannot".
** PEPPOL-T16-R006, PEPPOL-T19-R006 and PEPPOL-T77-R003 now say SHALL NOT instead of "SHALL not".
** PEPPOL-T76-R007 to PEPPOL-T76-R010 and PEPPOL-T116-R007 to PEPPOL-T116-R010 now say MUST and MUST NOT instead of "must" and "must NOT".
** PEPPOL-T77-R005 and PEPPOL-T77-R007 now say SHALL instead of "may".
** PEPPOL-T114-R004 and PEPPOL-T114-R005 now say MUST NOT instead of "MUST not".
* PEPPOL-T114-R008 stays a warning. The text now says SHOULD instead of MUST. This is an existing warning, not a new rule, so it does not become fatal.
